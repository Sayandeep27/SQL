# MySQL UNION vs UNION ALL

---

## Overview

`UNION` and `UNION ALL` are SQL operators used to **combine results from multiple SELECT queries** into a single result set.

They are commonly used when:

* Data exists in multiple tables with the same structure
* You want to merge query results
* You want to remove or keep duplicates

# 2. What is UNION

`UNION` combines results from multiple SELECT queries **and removes duplicate rows**.

### Syntax

```sql
SELECT column_list FROM table1
UNION
SELECT column_list FROM table2;
```

---

# Example: UNION Query

```sql
SELECT name FROM students_2023
UNION
SELECT name FROM students_2024;
```

---

## Result

| name    |
| ------- |
| Alice   |
| Bob     |
| Charlie |
| David   |
| Eva     |

Notice:

`Charlie` appears only **once** because UNION removes duplicates.

---

# How UNION Works Internally

Steps:

1. Execute first SELECT
2. Execute second SELECT
3. Combine both results
4. Remove duplicate rows
5. Return final dataset

Because duplicate checking is required, **UNION is slower than UNION ALL**.

---

# 3. What is UNION ALL

`UNION ALL` combines results from multiple SELECT queries **without removing duplicates**.

### Syntax

```sql
SELECT column_list FROM table1
UNION ALL
SELECT column_list FROM table2;
```

---

# Example: UNION ALL Query

```sql
SELECT name FROM students_2023
UNION ALL
SELECT name FROM students_2024;
```

---

## Result

| name    |
| ------- |
| Alice   |
| Bob     |
| Charlie |
| Charlie |
| David   |
| Eva     |

Here **Charlie appears twice** because duplicates are allowed.

---

# 4. Key Differences

| Feature            | UNION    | UNION ALL    |
| ------------------ | -------- | ------------ |
| Combines results   | Yes      | Yes          |
| Removes duplicates | Yes      | No           |
| Performance        | Slower   | Faster       |
| Sorting internally | Required | Not required |

---

# 5. Rules for Using UNION

To use UNION correctly, queries must follow these rules.

## Rule 1: Same Number of Columns

Correct:

```sql
SELECT id,name FROM students_2023
UNION
SELECT id,name FROM students_2024;
```

Incorrect:

```sql
SELECT id,name FROM students_2023
UNION
SELECT name FROM students_2024;
```

---

## Rule 2: Compatible Data Types

Examples:

| Table1 Column | Table2 Column | Valid             |
| ------------- | ------------- | ----------------- |
| INT           | INT           | Yes               |
| VARCHAR       | VARCHAR       | Yes               |
| INT           | VARCHAR       | Usually converted |

---

## Rule 3: Column Names Come From First Query

Example:

```sql
SELECT name FROM students_2023
UNION
SELECT name FROM students_2024;
```

Final column name will be **name**.

---

# 6. UNION with ORDER BY

`ORDER BY` must appear **only once at the end of the query**.

### Example

```sql
SELECT name FROM students_2023
UNION
SELECT name FROM students_2024
ORDER BY name;
```

---

## Sorted Result

| name    |
| ------- |
| Alice   |
| Bob     |
| Charlie |
| David   |
| Eva     |

---

# 7. UNION with Multiple Tables

You can combine more than two queries.

```sql
SELECT name FROM table1
UNION
SELECT name FROM table2
UNION
SELECT name FROM table3;
```

# 9. Performance Tip

Use:

```
UNION ALL
```

when:

* duplicates are acceptable
* faster performance is required

Use:

```
UNION
```

when:

* duplicate rows must be removed

---

# 10. Quick Memory Trick

```
UNION = Unique rows

UNION ALL = All rows
```

| UNION ALL   | Combines results and keeps duplicates    |
| Performance | UNION slower due to duplicate removal    |
| Usage       | Merge query results from multiple tables |
