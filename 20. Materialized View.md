# 📊 SQL Materialized Views – Complete Guide

---

## 📌 Overview

A **Materialized View** is a database object that **stores the result of a query physically**.

Unlike a normal view, which runs the query every time, a materialized view **precomputes and saves the data**, making it much faster for read operations.

---

## ⚡ Key Idea

* **View** → Just a saved query (no data stored)
* **Materialized View** → Stored query result (data stored like a table)

---

## 🎯 Why Use Materialized Views?

Materialized views are mainly used for:

* Improving query performance
* Reducing computation time for complex queries
* Optimizing reporting and dashboards
* Handling large datasets efficiently

---

## 🧱 Syntax (General)

```sql
CREATE MATERIALIZED VIEW view_name AS
SELECT column1, column2
FROM table_name
WHERE condition;
```

---

## 📘 Example

### Create a Materialized View

```sql
CREATE MATERIALIZED VIEW total_sales AS
SELECT customer_id, SUM(amount) AS total_amount
FROM orders
GROUP BY customer_id;
```

### Query the Materialized View

```sql
SELECT * FROM total_sales;
```

---

## 🔄 Refreshing Materialized Views

Since data is stored, it can become outdated. You must refresh it.

### 🔹 Manual Refresh

```sql
REFRESH MATERIALIZED VIEW total_sales;
```

---

### 🔹 Automatic Refresh (DB-specific)

#### PostgreSQL

```sql
REFRESH MATERIALIZED VIEW total_sales;
```

(Note: No built-in automatic refresh, use cron/jobs)

---

#### Oracle

```sql
CREATE MATERIALIZED VIEW total_sales
REFRESH FAST ON COMMIT
AS
SELECT customer_id, SUM(amount)
FROM orders
GROUP BY customer_id;
```

---

## ⚖️ Materialized View vs View

| Feature        | View              | Materialized View         |
| -------------- | ----------------- | ------------------------- |
| Storage        | ❌ No              | ✅ Yes                     |
| Speed          | Slower            | Faster                    |
| Data Freshness | Always up-to-date | Needs refresh             |
| Use Case       | Simple queries    | Heavy queries / reporting |

---

## 🧠 When to Use Materialized Views

Use them when:

* Data does not change frequently
* Queries are complex (joins, aggregations)
* You need fast read performance
* Used in dashboards or reports

---

## ⚠️ Important Notes

* Requires extra storage
* Needs refresh strategy
* Not all databases support it natively

---

## 🏢 Database Support

| Database   | Support               |
| ---------- | --------------------- |

| Oracle     | ✅ Yes                 |

| Snowflake  | ✅ Yes                 |
| BigQuery   | ✅ Yes (limited)       |

---

## 🛠 MySQL Workaround (No Native Support)

Since MySQL does not support materialized views directly, you can simulate it using a table.

### Step 1: Create Table

```sql
CREATE TABLE total_sales AS
SELECT customer_id, SUM(amount) AS total_amount
FROM orders
GROUP BY customer_id;
```

### Step 2: Refresh Manually

```sql
TRUNCATE TABLE total_sales;

INSERT INTO total_sales
SELECT customer_id, SUM(amount)
FROM orders
GROUP BY customer_id;
```

## 📊 Real-Life Use Case

### Example: Sales Dashboard

Instead of calculating total sales every time:

* Create materialized view once
* Refresh daily
* Fetch results instantly

---

## 🚀 Performance Tip

You can add indexes to materialized views for even faster queries:

```sql
CREATE INDEX idx_customer_id ON total_sales(customer_id);
```
