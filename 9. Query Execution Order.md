# MySQL Query Execution Order

## Overview

Understanding the **order in which SQL clauses execute** is essential when writing correct and optimized queries.

Although we write SQL queries in this order:

```
SELECT
FROM
WHERE
GROUP BY
HAVING
ORDER BY
LIMIT
```

MySQL actually **processes them in a different order internally**.

---

# Actual Execution Order in MySQL

1. FROM
2. WHERE
3. GROUP BY
4. HAVING
5. SELECT
6. ORDER BY
7. LIMIT

# Step‑by‑Step Clause Explanation

## 1. FROM

### Purpose

Specifies **which table MySQL should read data from**.

### Example

```sql
SELECT *
FROM employees;
```

### Result

| emp_id | name   | department | salary | city      |
| ------ | ------ | ---------- | ------ | --------- |
| 1      | Rahul  | IT         | 60000  | Mumbai    |
| 2      | Priya  | HR         | 45000  | Delhi     |
| 3      | Aman   | IT         | 70000  | Bangalore |
| 4      | Neha   | Finance    | 65000  | Mumbai    |
| 5      | Vikram | IT         | 80000  | Pune      |
| 6      | Anjali | HR         | 50000  | Delhi     |

---

## 2. WHERE

### Purpose

Filters rows **before grouping or aggregation**.

### Example

```sql
SELECT *
FROM employees
WHERE salary > 60000;
```

### Result

| emp_id | name   | department | salary | city      |
| ------ | ------ | ---------- | ------ | --------- |
| 3      | Aman   | IT         | 70000  | Bangalore |
| 4      | Neha   | Finance    | 65000  | Mumbai    |
| 5      | Vikram | IT         | 80000  | Pune      |

---

## 3. GROUP BY

### Purpose

Groups rows that have the **same values** in specified columns.

### Example

```sql
SELECT department
FROM employees
GROUP BY department;
```

### Result

| department |
| ---------- |
| IT         |
| HR         |
| Finance    |

---

## 4. Aggregate Functions

Aggregate functions perform **calculations on grouped data**.

Common aggregate functions:

| Function | Purpose       |
| -------- | ------------- |
| COUNT()  | Count rows    |
| SUM()    | Total value   |
| AVG()    | Average       |
| MIN()    | Minimum value |
| MAX()    | Maximum value |

### Example

```sql
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department;
```

### Result

| department | avg_salary |
| ---------- | ---------- |
| IT         | 70000      |
| HR         | 47500      |
| Finance    | 65000      |

---

## 5. HAVING

### Purpose

Filters **grouped data**.

Unlike WHERE, it works **after GROUP BY**.

### Example

```sql
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 60000;
```

### Result

| department | avg_salary |
| ---------- | ---------- |
| IT         | 70000      |
| Finance    | 65000      |

---

## 6. SELECT

### Purpose

Chooses **which columns or expressions to display**.

### Example

```sql
SELECT name, salary
FROM employees;
```

### Result

| name   | salary |
| ------ | ------ |
| Rahul  | 60000  |
| Priya  | 45000  |
| Aman   | 70000  |
| Neha   | 65000  |
| Vikram | 80000  |
| Anjali | 50000  |

---

## 7. ORDER BY

### Purpose

Sorts the result set.

### Example

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC;
```

### Result

| name   | salary |
| ------ | ------ |
| Vikram | 80000  |
| Aman   | 70000  |
| Neha   | 65000  |
| Rahul  | 60000  |
| Anjali | 50000  |
| Priya  | 45000  |

---

## 8. LIMIT

### Purpose

Restricts the **number of rows returned**.

### Example

```sql
SELECT name, salary
FROM employees
ORDER BY salary DESC
LIMIT 3;
```

### Result

| name   | salary |
| ------ | ------ |
| Vikram | 80000  |
| Aman   | 70000  |
| Neha   | 65000  |

---

# Full Example Query

```sql
SELECT department, AVG(salary) AS avg_salary
FROM employees
WHERE salary > 45000
GROUP BY department
HAVING AVG(salary) > 60000
ORDER BY avg_salary DESC
LIMIT 2;
```

---

# How MySQL Executes This Query

Step 1 — FROM employees

Step 2 — WHERE salary > 45000

Step 3 — GROUP BY department

Step 4 — Calculate AVG(salary)

Step 5 — HAVING AVG(salary) > 60000

Step 6 — SELECT department, AVG(salary)

Step 7 — ORDER BY avg_salary DESC

Step 8 — LIMIT 2

# Key Differences

| Clause   | Works On | Used For                    |
| -------- | -------- | --------------------------- |
| WHERE    | Rows     | Filter rows before grouping |
| GROUP BY | Rows     | Create groups               |
| HAVING   | Groups   | Filter groups               |
| ORDER BY | Result   | Sort results                |
| LIMIT    | Result   | Restrict rows               |

---

# Quick Memory Trick

Execution order:

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

Writing order:

```
SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
```

---

# Summary

* SQL clauses execute in a **different order than written**.
* **WHERE filters rows** before grouping.
* **GROUP BY creates groups**.
* **Aggregate functions compute values for groups**.
* **HAVING filters groups**.
* **SELECT chooses output columns**.
* **ORDER BY sorts the results**.
* **LIMIT restricts output rows**.
