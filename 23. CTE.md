# 📘 SQL CTEs and Subqueries — Complete Guide

---

## 🔹 What is a CTE?

A **CTE (Common Table Expression)** is a **temporary result set** that you define and use within a query.

👉 Think of it as a **named subquery** that makes your SQL:

* cleaner
* more readable
* reusable

---

## 🔹 Basic Syntax

```sql
WITH cte_name AS (
    SELECT column1, column2
    FROM table_name
    WHERE condition
)
SELECT *
FROM cte_name;
```

👉 Key points:

* Starts with **WITH**
* Exists only for that query
* You can use it like a **table**

---

## 🔹 Simple Example

### Problem:

Get employees with salary > 50,000

### Without CTE:

```sql
SELECT *
FROM (
    SELECT * FROM employees
) temp
WHERE salary > 50000;
```

### With CTE:

```sql
WITH high_salary AS (
    SELECT *
    FROM employees
)
SELECT *
FROM high_salary
WHERE salary > 50000;
```

👉 Same result, but **cleaner and easier to read**

---

## 🔹 Why Use CTE?

### 1. Improves Readability

Break complex queries into steps

### 2. Avoid Repetition

Reuse same logic

### 3. Better Debugging

You can test each part separately

---

## 🔹 CTE with Aggregation Example

### Problem:

Find average salary per department, then filter > 60,000

```sql
WITH dept_avg AS (
    SELECT department, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department
)
SELECT *
FROM dept_avg
WHERE avg_salary > 60000;
```

---

## 🔹 Multiple CTEs

```sql
WITH cte1 AS (
    SELECT * FROM employees
),
cte2 AS (
    SELECT department, COUNT(*) AS total
    FROM cte1
    GROUP BY department
)
SELECT *
FROM cte2;
```

---

## 🔹 Recursive CTE (IMPORTANT)

Used for **hierarchical data** (like manager → employee)

### Example: Employee Hierarchy

```sql
WITH RECURSIVE emp_hierarchy AS (
    SELECT id, name, manager_id
    FROM employees
    WHERE manager_id IS NULL

    UNION ALL

    SELECT e.id, e.name, e.manager_id
    FROM employees e
    JOIN emp_hierarchy eh
    ON e.manager_id = eh.id
)
SELECT * FROM emp_hierarchy;
```

### How Recursive CTE Works

1. Base Query → starting point
2. Recursive Query → keeps calling itself
3. Stops when no new rows are found

| ----------------- | ---------- | ---------- |

## 🔹 Interview Example

### Find 2nd highest salary

```sql
WITH ranked AS (
    SELECT salary,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employees
)
SELECT salary
FROM ranked
WHERE rnk = 2;
```

# 🔥 CTE vs Subquery — When to Use

---

## 🔹 Core Difference

* **CTE** → readability + reuse + step-by-step logic
* **Subquery** → small, one-time logic

---

## 🔹 Detailed Comparison

| Feature             | CTE          | Subquery                   |
| ------------------- | ------------ | -------------------------- |
| Readability         | ✅ Very clear | ❌ Messy in complex queries |
| Reusability         | ✅ Can reuse  | ❌ Cannot reuse             |
| Complexity handling | ✅ Best       | ❌ Poor                     |
| Recursive queries   | ✅ Yes        | ❌ No                       |
| Scope               | Whole query  | Local                      |
| Performance         | ⚖️ Similar   | ⚖️ Similar                 |

---

## 🔹 When to Use CTE

### 1. Complex Queries

```sql
WITH step1 AS (
    SELECT * FROM sales WHERE amount > 1000
),
step2 AS (
    SELECT region, SUM(amount) AS total
    FROM step1
    GROUP BY region
)
SELECT * FROM step2;
```

---

### 2. Reuse Logic

```sql
WITH filtered AS (
    SELECT * FROM employees WHERE salary > 50000
)
SELECT * FROM filtered
UNION ALL
SELECT * FROM filtered;
```

---

### 3. Recursive Problems

* Hierarchy
* Tree
* Graph

---

### 4. Window Functions

```sql
WITH ranked AS (
    SELECT name, salary,
           RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employees
)
SELECT * FROM ranked WHERE rnk <= 3;
```

---

## 🔹 When to Use Subquery

### 1. Simple Logic

```sql
SELECT name
FROM employees
WHERE salary > (
    SELECT AVG(salary) FROM employees
);
```

---

### 2. Inline Filtering

```sql
SELECT *
FROM orders
WHERE customer_id IN (
    SELECT id FROM customers WHERE city = 'Mumbai'
);
```

---

### 3. EXISTS

```sql
SELECT name
FROM employees e
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.emp_id = e.id
);
```

---

## 🔹 Intuition

* One small idea → Subquery
* Multiple steps → CTE

---

## 🔹 Side-by-Side Example

### Subquery

```sql
SELECT department, AVG(salary)
FROM employees
GROUP BY department
HAVING AVG(salary) > 60000;
```

### CTE

```sql
WITH dept_avg AS (
    SELECT department, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department
)
SELECT *
FROM dept_avg
WHERE avg_salary > 60000;
```

---

## 🔹 Interview Answer

“I use subqueries for simple, one-time filtering logic. I prefer CTEs when queries become complex, require reuse, or involve multiple steps or recursion. CTEs improve readability and maintainability.”

---

## 🔹 Final Rule

👉 Use **CTE** when:

* Query is long
* Logic reused
* Need recursion
* Need clarity

👉 Use **Subquery** when:

* Query is short
* Used once
* Simple filtering

---

## 🔹 Notes on Performance

* In most databases: execution is similar
* Focus on readability and maintainability
