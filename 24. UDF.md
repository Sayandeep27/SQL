# 📘 SQL User Defined Functions (UDF) — Complete Guide

---

## 📌 What is a UDF?

A **User Defined Function (UDF)** in SQL is a function that is **created by the user** to perform a specific task.

It behaves just like built-in functions such as:

* `SUM()`
* `AVG()`
* `COUNT()`

👉 The key difference: **You define the logic yourself.**

---

## 🎯 Why Use UDF?

Using UDFs helps in writing **clean, reusable, and modular SQL code**.

### ✅ Benefits:

* Avoid repeating the same logic multiple times
* Improve query readability
* Encapsulate business logic
* Make maintenance easier

---

## 🧠 Types of UDF in SQL

There are **3 main types of UDFs**:

| Type                    | Description              | Returns            |
| ----------------------- | ------------------------ | ------------------ |
| Scalar UDF              | Returns a single value   | INT, VARCHAR, etc. |
| Table-Valued UDF        | Returns a table          | TABLE              |
| Inline Table-Valued UDF | Optimized table function | TABLE              |

---

# 🔹 1. Scalar UDF (Single Value Function)

A **Scalar UDF** returns a **single value**.

### 📌 Use Case:

When you need to compute something like:

* Bonus
* Tax
* Discount

---

### ✅ Example: Calculate Bonus

```sql
CREATE FUNCTION calculate_bonus (@salary INT)
RETURNS INT
AS
BEGIN
    RETURN @salary * 0.10
END;
```

---

### 🔹 Usage:

```sql
SELECT name, salary, dbo.calculate_bonus(salary) AS bonus
FROM employees;
```

---

### 📊 Output Example:

| name | salary | bonus |
| ---- | ------ | ----- |
| A    | 50000  | 5000  |

---

### ⚠️ Important Notes:

* Returns only **one value**
* Can be used in `SELECT`, `WHERE`, `ORDER BY`
* **Slower on large datasets** (row-by-row execution)

---

# 🔹 2. Table-Valued UDF

A **Table-Valued Function** returns a **table instead of a single value**.

👉 You can use it like a normal table in queries.

---

### ✅ Example: Get Employees by Department

```sql
CREATE FUNCTION get_employees_by_dept (@dept_id INT)
RETURNS TABLE
AS
RETURN
(
    SELECT *
    FROM employees
    WHERE department_id = @dept_id
);
```

---

### 🔹 Usage:

```sql
SELECT *
FROM get_employees_by_dept(101);
```

---

### 📌 Key Points:

* Returns multiple rows
* Can be joined with other tables
* Faster than scalar UDF

---

# 🔹 3. Inline Table-Valued UDF

This is a **simplified and optimized version** of table-valued functions.

👉 No `BEGIN...END` block
👉 Direct `RETURN` statement

---

### ✅ Example: High Salary Employees

```sql
CREATE FUNCTION high_salary_employees (@min_salary INT)
RETURNS TABLE
AS
RETURN
(
    SELECT name, salary
    FROM employees
    WHERE salary > @min_salary
);
```

---

### 📌 Why Inline is Better?

* Better performance
* Query optimizer can optimize it easily
* Works like a **parameterized view**

---

# 🔥 Scalar vs Table UDF — Comparison

| Feature     | Scalar UDF    | Table UDF   |
| ----------- | ------------- | ----------- |
| Returns     | Single value  | Table       |
| Usage       | SELECT, WHERE | FROM clause |
| Performance | Slower        | Faster      |
| Execution   | Row-by-row    | Set-based   |

---

# ⚖️ UDF vs Stored Procedure

| Feature      | UDF                              | Stored Procedure            |
| ------------ | -------------------------------- | --------------------------- |
| Return Type  | Must return value                | Can return multiple results |
| Usage        | Inside queries                   | Executed separately         |
| Side Effects | No data modification (generally) | Can modify data             |
| Use Case     | Calculations                     | Complex workflows           |

# 🏢 Real-World Examples

---

## ✔ Example 1: Tax Calculation

```sql
CREATE FUNCTION calculate_tax (@salary INT)
RETURNS INT
AS
BEGIN
    RETURN @salary * 0.20
END;
```

---

## ✔ Example 2: Full Name Formatter

```sql
CREATE FUNCTION full_name (@first VARCHAR(50), @last VARCHAR(50))
RETURNS VARCHAR(100)
AS
BEGIN
    RETURN @first + ' ' + @last
END;
```

---

## ✔ Example 3: Filter High Salary Employees

```sql
SELECT *
FROM high_salary_employees(60000);
```

---

# ⚠️ Important Limitations of UDF

* Cannot perform `INSERT`, `UPDATE`, `DELETE` (in most SQL systems)
* No transaction control
* Limited error handling
* Scalar UDF can hurt performance on large data

---

# 🚀 When to Use UDF

### ✅ Use UDF when:

* Logic is reused frequently
* Business rules need abstraction
* You want cleaner SQL queries

---

### ❌ Avoid UDF when:

* Performance is critical
* Large datasets involved
* Logic can be written directly in SQL

---

# 💡 Pro Tips (Interview + Real World)

* Prefer **Inline Table UDF over Scalar UDF**
* Avoid scalar UDF in large queries (can cause slow performance)
* Use UDF for **modularity, not heavy computation**
* Think of UDF as **"Reusable SQL logic block"**

---

# 🧾 Summary

* UDF = Custom SQL Function
* 3 Types → Scalar, Table, Inline
* Helps in reusable and clean SQL
* Be careful with performance (especially scalar UDF)

---

# ⭐ Final Thought

👉 UDFs are powerful, but should be used **wisely**.

Use them for **clarity and reuse**, not for heavy processing.
