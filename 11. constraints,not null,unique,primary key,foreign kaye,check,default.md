# MySQL Constraints – Complete Guide

## Introduction

Constraints are rules applied to table columns to ensure **data integrity, accuracy, and reliability** in a database.

They control what type of data can be inserted into a table.

---

# Types of Constraints in MySQL

| Constraint  | Purpose                             |
| ----------- | ----------------------------------- |
| NOT NULL    | Prevents NULL values                |
| UNIQUE      | Ensures all values are different    |
| PRIMARY KEY | Unique identifier for each row      |
| FOREIGN KEY | Links two tables                    |
| CHECK       | Restricts values based on condition |
| DEFAULT     | Assigns default value               |

# 1 NOT NULL Constraint

## Definition

The **NOT NULL constraint ensures that a column cannot have NULL values**.

## Syntax

```sql
CREATE TABLE students (
 id INT NOT NULL,
 name VARCHAR(50) NOT NULL
);
```

## Example Table

| id | name  |
| -- | ----- |
| 1  | Rahul |
| 2  | Priya |

Attempting to insert NULL will cause an error.

```sql
INSERT INTO students VALUES (3,NULL);
```

---

# 2 UNIQUE Constraint

## Definition

The **UNIQUE constraint ensures that all values in a column are different**.

## Syntax

```sql
CREATE TABLE users (
 email VARCHAR(100) UNIQUE
);
```

## Example Table

| id | email                             |
| -- | --------------------------------- |
| 1  | [a@email.com](mailto:a@email.com) |
| 2  | [b@email.com](mailto:b@email.com) |

Duplicate values are not allowed.

---

# 3 PRIMARY KEY

## Definition

A **PRIMARY KEY uniquely identifies each record in a table**.

Properties:

* Must be unique
* Cannot contain NULL
* Only one primary key per table

## Syntax

```sql
CREATE TABLE employees (
 id INT PRIMARY KEY,
 name VARCHAR(50)
);
```

## Example Table

| id | name  |
| -- | ----- |
| 1  | Rahul |
| 2  | Aman  |

---

# 4 FOREIGN KEY

## Definition

A **FOREIGN KEY links one table with another table**.

It ensures **referential integrity**.

## Example Tables

### Department Table

| DepartmentID | DepartmentName |
| ------------ | -------------- |
| 101          | HR             |
| 102          | IT             |

### Students Table

| StudentID | Name  | DepartmentID |
| --------- | ----- | ------------ |
| 1         | Rahul | 101          |
| 2         | Priya | 102          |

## Syntax

```sql
CREATE TABLE students (
 StudentID INT PRIMARY KEY,
 Name VARCHAR(50),
 DepartmentID INT,
 FOREIGN KEY (DepartmentID) REFERENCES departments(DepartmentID)
);
```

---

# 5 CHECK Constraint

## Definition

The **CHECK constraint ensures that values in a column satisfy a specific condition**.

## Syntax

```sql
CREATE TABLE students (
 age INT,
 CHECK (age >= 18)
);
```

## Example

| id | age |
| -- | --- |
| 1  | 20  |
| 2  | 21  |

If we try:

```sql
INSERT INTO students VALUES (2,15);
```

It will fail.

---

# 6 DEFAULT Constraint

## Definition

The **DEFAULT constraint provides a default value when no value is specified**.

## Syntax

```sql
CREATE TABLE employees (
 status VARCHAR(20) DEFAULT 'Active'
);
```

## Example

```sql
INSERT INTO employees () VALUES();
```

Result

| status |
| ------ |
| Active |

# Adding Constraints Using ALTER TABLE

## Add NOT NULL

```sql
ALTER TABLE students
MODIFY name VARCHAR(50) NOT NULL;
```

## Add UNIQUE

```sql
ALTER TABLE students
ADD CONSTRAINT unique_email UNIQUE(email);
```

## Add PRIMARY KEY

```sql
ALTER TABLE students
ADD PRIMARY KEY(StudentID);
```

## Add FOREIGN KEY

```sql
ALTER TABLE students
ADD FOREIGN KEY (DepartmentID)
REFERENCES departments(DepartmentID);
```

# Best Practices

* Always use **PRIMARY KEY** in tables
* Use **FOREIGN KEY** to maintain relationships
* Use **CHECK** for validation
* Use **DEFAULT** for common values

---

# Conclusion

Constraints are essential in MySQL for maintaining **data integrity, consistency, and reliability**.

They prevent invalid data from entering the database and help maintain relationships between tables.
